# MPN Lookup (React Native)

Mobile app that looks up the Most Probable Number (MPN) and 95% confidence range for
IDEXX QuantiTray®, QuantiTray®/2000 and Legiolert tests from a count of positive wells.

Built from the [Obytes starter](https://github.com/obytes/react-native-template-obytes)
v7.0.2. We are incrementally moving toward parity with the Obytes template, now targeting
v10 (see "Obytes v10 upgrade plan" below). Keep changes small and one concern per PR.

## Stack

- Expo SDK 57, React Native 0.86, React 19.2 (New Architecture only), Expo Router 57.
  Import React Navigation APIs from `expo-router/react-navigation`, not `@react-navigation/*`
- Reanimated 4.5 + react-native-worklets 0.10 (`babel-preset-expo` adds the worklets Babel plugin;
  both are mocked in `jest-setup.ts`)
- TypeScript 6 (no `baseUrl`; aliases are in `paths`), Uniwind + Tailwind 4 (theme in `src/global.css`; `uniwind-types.d.ts` is generated
  by Metro, commit it as generated), Zustand 5, Zod 4, i18next 25, React Query, MMKV 4 (Nitro Modules; mocked in `jest-setup.ts`)
- Sentry (`@sentry/react-native` 7.11, the version Expo SDK 57 supports; let `npx expo install --fix` pick it).
  Local release builds need `SENTRY_DISABLE_AUTO_UPLOAD=true`, as in CI
- Jest + React Native Testing Library (unit), Maestro (end-to-end)
- pnpm only (`preinstall` enforces it)

## Layout

```
src/app/            Expo Router routes. _layout.tsx initializes Sentry; index.tsx is the only screen
src/components/     App UI: button-view.tsx (home + navigation), lookup-component.tsx (inputs + results)
src/util/           MPN lookup logic
src/ui/, src/core/  Obytes starter UI kit and helpers (mostly unused by the app today)
__tests__/          Unit tests for the app code (src/ui/*.test.tsx cover the starter UI kit)
.maestro/flows/     Maestro end-to-end flows (use the testIDs in src/components)
plugins/            Local Expo config plugins
env.js              Build/client env validation (zod). Bundle IDs get a .<APP_ENV> suffix except production
```

`ios/` and `android/` are generated by `expo prebuild` and gitignored. Never hand-edit them;
use `app.config.ts` or a config plugin in `plugins/` so changes survive `prebuild --clean`.

## Commands

```bash
pnpm start                 # Metro dev server
pnpm ios / pnpm android    # Native dev build and run
pnpm prebuild --clean      # Regenerate ios/ and android/
pnpm lint                  # ESLint (also enforces formatting)
pnpm lint:fix              # ESLint auto-fix, including formatting
pnpm type-check            # tsc --noEmit
pnpm test                  # Jest
pnpm check-all             # lint + type-check + translations lint + test
maestro test .maestro --env APP_ID=com.mpnlookuprn.development   # E2E on a running emulator/simulator
```

## Setup

- **Tools:** Node 22 (same as CI), Xcode with an iOS simulator runtime, CocoaPods, Android Studio
  with JDK 17 and an API 34+ emulator. Run `corepack enable` so the `packageManager` pnpm version
  is used.
- **Env files:** `.env.development` and `.env.local` are not in git and must never be committed
  (`.env.local` holds tokens). `env.js` requires `API_URL`, `VAR_NUMBER`, `VAR_BOOL` and
  `SECRET_KEY`. Placeholder values like the ones CI uses are enough to build and run.
- **Maestro:** use the CI version,
  `curl -Ls "https://get.maestro.mobile.dev" | MAESTRO_VERSION=2.12.1 bash`.

## Testing

- Every behavior change gets a Jest test. `__tests__/mpn.lookup.test.ts` holds the reference values.
- UI flows a user can see get a Maestro flow in `.maestro/flows/`. Select elements by `testID`;
  add a `testID` to the component if one is missing. Start each flow with
  `- runFlow: ../subflows/launch-clean.yaml` (not a bare `launchApp`): it retries the clean launch,
  because the Android CI emulator sometimes kills the relaunched app ("Destroy timeout of remove-task").
- Run Maestro against a release build (`SENTRY_DISABLE_AUTO_UPLOAD=true pnpm ios --configuration Release`).
  The flows use `clearState`, which leaves a development build stuck on the Expo dev launcher.
- App IDs: `com.mpnlookuprn.<env>` (development, staging) and `com.mpnlookuprn` (production).

## CI (GitHub Actions)

- Every PR: lint, type-check, Jest (`lint-ts.yml`, `type-check.yml`, `test.yml`).
- `e2e-android.yml`: builds a staging release APK and runs Maestro on a Linux x86_64 emulator.
  Runs on pushes to main and on PRs labeled `e2e-android`.
- CI has no `.env.*` files, so `.github/actions/setup-jdk-generate-apk` supplies placeholder
  env values and sets `SENTRY_DISABLE_AUTO_UPLOAD=true`.

## Conventions

- Formatting is ESLint Stylistic via `@antfu/eslint-config` (`eslint.config.mjs`), as in the
  Obytes v9 template. There is no Prettier; run `pnpm lint:fix` instead.
- Conventional Commits (commitlint), e.g. `feat:`, `fix:`, `chore:`, `ci:`, `test:`.
- No direct commits to main; the pre-commit hook blocks it and runs type-check, lint-staged and Jest.
- Prefer existing Obytes patterns when adding features, so later template upgrades stay easy.

## Obytes v10 upgrade plan

Target: Obytes v10, which is [PR #543](https://github.com/obytes/react-native-template-obytes/pull/543)
(branch `chore/template-upgrade`) until it is released. Compare against that branch, and follow its
"Migrating to v10" guide once published. Each step is its own PR to `main` (some CI only runs on
PRs to `main`), and the app must build and pass Maestro on both platforms after each one.
Tick steps off here as they merge.

- [x] 1. **Finish v9 parity:** NativeWind 4 + Tailwind 3 → Uniwind + Tailwind 4, `tailwind-variants` 3
  (#21). Still open, optional: react-hook-form → TanStack Form (only `src/ui` uses it).
- [x] 2. **Expo SDK 57** (React Native 0.86, React 19.2) (#22). Also targets Android 16 (API 36),
  which Google Play requires for updates from Oct 31, 2026.
- [ ] 3. **Dependencies:** i18next 26, MMKV 4.3, Nitro Modules 0.37. Replace `react-native-restart`
  with Expo's `reloadAppAsync`, remove unused packages. (`react-native-edge-to-edge` was already
  removed in #22.)
- [x] 4. **TypeScript 6** (#22, because Expo 57 requires it): `paths` without `baseUrl`, `css.d.ts`.
- [ ] 5. **React Compiler** (`babel-plugin-react-compiler`). Obytes also drops
  `eslint-plugin-react-compiler`, whose rules now ship in `eslint-plugin-react-hooks` 7.
- [ ] 6. **Bun replaces pnpm:** `packageManager`, install guard, CI, husky hooks (fixes `post-merge`
  checking the nonexistent `pnpm-lock.yml`) and the commands in this file. Bun loads `.env`,
  `.env.local` etc. into every script by default, which would expose the `.env.local` tokens and
  bypass `EXPO_NO_DOTENV`/`env.js`. Set `env = false` in `bunfig.toml` and confirm `bun run start`
  no longer sees `.env.local` values. `bun install` converts `pnpm-lock.yaml` to `bun.lock` itself.
- [ ] 7. **Optional:** Nitro Fetch (the app makes no network calls today) and the opt-in Argent setup.
- [ ] 8. **Fix the app layout** (after the upgrade steps): on iOS the Back button is cut off by the
  bottom of the screen. `src/components/button-view.tsx` uses fixed sizes (`width: 412`,
  `height: 580`, 160pt of header padding, Back pulled up with `top: -150`). Replace them with a
  flexible layout in Uniwind `className`s: header at the top, test area filling and scrolling, Back
  pinned to the bottom above the safe-area inset. Add a Maestro check that Back is fully visible.
  Replace React Native's deprecated `SafeAreaView` in `src/app/index.tsx` (it does nothing on
  Android) with `react-native-safe-area-context`: Android 16 forces edge-to-edge, so without real
  insets content can sit under the system bars. Do this before the next Play Store release.

## Known local-environment issues

- Xcode 27 replaced Simulator.app with DeviceHub. Expo CLI 57 finds DeviceHub, so `pnpm ios` works
  (the CLI 54 patch was removed). Expo's fix for `run:ios` treating `devicectl`-listed simulators as
  physical devices only arrives in SDK 58; if a simulator install fails that way, pass `--device <udid>`.
- Building with the iOS 27 SDK requires iOS scene support; `expo-build-properties`
  (`ios.enableSceneSupport`) in `app.config.ts` turns it on.
- Xcode 27 requires pod deployment targets ≥ iOS 15; `plugins/with-ios-pods-deployment-target.js` handles it.
- Xcode 27's clang can't compile fmt 11 (React Native 0.76.9+) as C++20;
  `plugins/with-ios-fmt-cxx17.js` builds that one pod as C++17.
- If a native package fails to compile with the iOS 27 SDK, patch it with `pnpm patch`
  (`patchedDependencies`) and drop the patch once an upgrade brings a fixed version.
- Maestro on iOS can't match `id` and `text` in one selector (React Native nests the text in a
  child element). Assert them separately. Don't use `hideKeyboard`; tap outside the inputs instead.
- Hermes has no `Intl.PluralRules`, so i18next falls back to English-style `one`/`other` plurals.
  No translation uses plurals today; add an `Intl.PluralRules` polyfill before adding Arabic ones.
